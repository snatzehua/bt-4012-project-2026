## Context

See proposal.md for motivation. The completed extension at reports/baf-recall-weighted-extension-v1/ made 36 new fits and 288 forward policy comparisons without beating macro F2 0.3278015781. Its best added strategy scored 0.3261. Balanced LightGBM remains the development-selected reference, while the old unweighted LightGBM policy has the stronger observed consumed-month-7 F2 (0.37688442 versus 0.36440856). Both must remain visible.

The four completed studies have frozen source/config/software/data identities and selection/access records. Keep them unchanged. Base v2 remains the same checksum-verified 1M-row synthetic dataset; months 0-6 are reused development data and month 7 is already consumed. Newly scoring earlier development months does not create new independent evidence.

## Goals / Non-Goals

**Goals:** Test whether complementary scores contain useful information that a learned low-dimensional combination can exploit, with separate single-member controls and strict time boundaries at base-model, combiner and policy stages. Seek a measured F2 gain over both relevant references, report failures and limit uncertainty claims to their actual scope.

**Non-Goals:** Change beta, impose a 1% workload, promise 90% recall, select from month-7 performance, alter old recipes, treat weighted outputs as calibrated probabilities, add raw applicant features to the combiner, or claim independent confirmation from repeated tuning. No generic random-fold stacking benchmark is included.

## Decisions

1. **Fixed members and unchanged applicant preprocessing.** Use the exact existing recipes from configs/improvements.json: baseline_balanced, native31, catboost_engineered6 and logistic_engineered. The balanced baseline uses its original train-fitted imputation/one-hot pipeline; native31 uses 29 original predictors, numeric NaNs and training-only categorical levels; CatBoost and engineered logistic use their existing 65-feature row-local bundle with their documented training-only preprocessing. Logistic retains C=0.1. Each base model trains on every month before its prediction month. No new member search or base hyperparameter search is included. Alternatives considered: more class-weight/window search has already failed; four fixed members allow a direct test of distinct modelling information with manageable meta-level complexity.

2. **Early out-of-time base predictions.** For each of the four members, generate scores for months 1/2/3 using training months 0, 0-1 and 0-2 respectively. Reuse exact compatible month-4/5/6 predictions from prior studies. Reuse the old unweighted baseline on 4/5/6 as an additional comparator. This yields 27 base candidate/month results: 12 early fits plus 15 verified reuses with current caches. Without caches, reproduce all 27 into the new destination. Verify training indices and class counts, maximum training month, source/config/software identity, score hashes, AP/ROC and exact evaluation IDs/labels. Numerical/category processing sees only eligible training rows; row-local engineered values may be computed once without using target/time. Missing caches never trigger writes to old study directories.

3. **Nested chronological combiner timing.** For each combiner preset, predict months 4/5/6. The month-4 combiner trains on the earlier base prediction rows from 1/2/3; month 5 trains on 1-4; month 6 trains on 1-5. Every such base prediction is itself out of time. Fit combiner preprocessing only on its eligible earlier prediction rows. Retain chronological combiner predictions for 4/5/6 as policy training data: month-5 rules use combiner predictions from 4, and month-6 rules use 4/5. Never fit a decision rule on a combiner's own in-sample training predictions. An alternative using only existing 4/5/6 base predictions would have no earlier out-of-time combiner prediction available for month-5 policy fitting; the extra early fits solve that boundary explicitly.

4. **Finite combiner grid and matched controls.** Use LogisticRegression with L2, lbfgs, max_iter=1000, tol=1e-6, seed 2026 and training-fitted StandardScaler. Cross two member sets (the four members versus baseline_balanced alone), two score representations (logit versus logit plus percentile), C {0.001,0.01,0.1}, and positive training weights {1,5}: 24 presets, each fitted for 4/5/6, yielding 72 combiner/control fits. Positive weights change training and are not an asserted bank cost ratio. The single-member controls use the exact same representation/C/weight/timing; they distinguish combination effects from score transformation and decision-policy effects. Regularization addresses correlated scores. A more flexible tree combiner is deferred because it adds interaction capacity and tuning before the simpler combination has been tested.

5. **Score representation.** Fixed logit input is log(p/(1-p)) after clipping each base score to [1e-6,1-1e-6]. The second representation adds each member's average-tie percentile (rank-.5)/n within its own prediction month. Four-member inputs have four or eight columns; single-member controls have one or two. Percentiles use scores and the same application batch only, never labels. Feature order, clip bound and member identity are fixed and recorded. Standardization uses the combiner's earlier training rows. The percentile representation requires batch inference, as in the previous rank extension; the logit-only variant does not. Weighted base/combiner scores are not claimed to be calibrated fraud probabilities.

6. **Policies, controls and selection.** Apply the existing pooled maximum-F2 threshold, latest-month maximum-F2 threshold and learned rank-fraction rules, preserving earlier-only sources, threshold/rank ties and exact rational ceiling. Retain both old baseline prediction/policy paths unchanged. There are 26 strategies (24 learned presets and two original baselines), three policies and two evaluated operating months (5/6), yielding 156 cross-fitted rows. Select by macro F2, recall, precision and deterministic candidate/policy ID. Report each stacking preset minus its matched single-member preset under the same policy, plus model-fixed policy contrasts and both old references. Report pooled confusion-count F2 separately. Reproduce balanced macro F2 0.3278015781 and unweighted 0.3226536849 before selection. All settings are analyst-selected, not approved group decisions.

7. **Freeze and exploratory transfer.** Freeze the selected candidate, its matched single-member control when a four-member stack wins, any base dependencies, combiner recipes, feature order, training-row identity, coefficients/scaler identity or deterministic fitting recipe, all three final policies learned from out-of-time combiner predictions 4/5/6, and source/config/software/data hashes. For a selected learned strategy, fit its final combiner and any required matched control on the available out-of-time base predictions from 1-6 before any further month-7 prediction access (at most two final combiner fits). Access is recorded separately with the selection digest. Reuse or refit only required month-7 base dependencies and both old baselines, then apply the already-fitted selected/control combiners and policies. The matched control's balanced member adds no base dependency beyond the baseline. If an old baseline remains selected, no final combiner is needed. Any month-7 observation is exploratory; it cannot determine model choice or trigger alteration of the frozen study. Other losing presets are not scored on month 7.

8. **Evidence, uncertainty and preservation.** Recompute every exported metric from saved predictions and rules: F2=5TP/(5TP+4FN+FP), F1/F3, precision/recall, AP/ROC, confusion counts, flagged fraction, MCC and balanced accuracy. Export all unsuccessful rows and matched contrasts. Use 500 paired row-bootstrap draws at fixed decisions, seed 1027, resampling within each evaluation month for development macro differences and comparing selected versus both baselines and its matched control where applicable. Intervals exclude training, model selection, between-month/generative uncertainty and multiplicity adjustment. A point gain supports only a named exploratory scope; intervals overlapping zero preclude clear-gain claims. Development improvement that fails consumed-period transfer is reported as failure to transfer, not overall improvement. The active performance objective remains unachieved without an appropriate measured gain. Audit all four preserved study identities and selection/access hashes before and after execution.

9. **Implementation and methodological verification.** Add configs/chronological-stacking.json, docs/chronological-stacking-protocol.md and additive baf modules/tests, with outputs/baf-chronological-stacking-v1/ ignored and reports/baf-chronological-stacking-v1/ exported. Use the pinned improvement environment; no new dependency is planned. Tests must reject in-sample/future-month base scores, combiner leakage and in-sample policy inputs, misaligned member rows/labels, changed caches and frozen identity changes; verify clipping, label-independent percentile ties, training-only scaling, fixed column order, matched controls, deterministic decisions and new-directory refits. Fit warnings require inspection. Reporting independently rebuilds metrics and intervals, verifies the actual selection and fit/access ordering, and renders an inspected figure. Fresh-clone reproduction restores small exported freeze records and can refit absent ignored predictions.

## Risks / Trade-offs

- The base models may make correlated errors and score learning may yield no gain → fixed members, matched single-model controls and retained negative evidence.
- Score distributions change as base training grows and fraud prevalence drifts → all combiner and operating checks are forward in time; report monthly changes and transfer failure.
- Many adaptive studies increase selection optimism → disclose earlier failures, predeclare this finite grid and do not present conditional intervals as selection-adjusted evidence.
- Strong weights or a better F2 can still create unacceptable false alarms → expose precision, false positives and review volume beside recall; no unsupported operating-cost claim.
- Generic stacking utilities can silently use inappropriate cross-validation → use explicit month-indexed prediction provenance and the nested chronology above.
- Missing caches increase compute → checkpoint per unchanged identity, refit into the new destination and preserve prior studies.

## Migration Plan

Declare config/protocol and preservation manifests; implement and test chronological base/combiner/policy boundaries; run the finite development search; export all contrasts; freeze before any further consumed-month access; score only selected dependencies; audit/report/inspect; update README/AGENTS/context and synchronize implemented requirements. Archive only after tasks and outputs are verified. Removing the new study's outputs leaves previous studies intact.

## Method references

Scikit-learn's [stacking documentation](https://scikit-learn.org/1.3/modules/generated/sklearn.ensemble.StackingClassifier.html) explains training the final estimator on out-of-sample base predictions and warns about fitting the combiner on data used to fit its base models. Its [time-series cross-validation documentation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html) explains the need to train before the evaluated period. This design implements explicit monthly stages instead of the default generic stacking cross-validation. These references justify leakage controls; they do not show that stacking improves this dataset.
